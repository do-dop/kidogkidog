# Kidogkidog 추가 작업: 포트폴리오·자소서 문안

기준: 2026-11-05까지의 코드, 커밋, 원본 영상 검증 기록과 오프라인 실험 보고서. 기존 프로젝트 소개는 [포트폴리오 정리](portfolio.md)를 참고한다. 아래 문안은 시퀀스 검색 담당인 박도연의 구현·검증을 중심으로 작성했다.

## 포트폴리오에 추가할 사례

### 제목

**영상 행동 검색을 ‘순서 답변’에서 ‘검증 가능한 장면 타임라인’으로 확장**

### 문제와 담당 역할

기존 검색은 관련 프레임을 찾을 수 있었지만, “처음에는 무엇을 했어?”, “수영장 장면 다음에는?”처럼 영상의 시간 관계를 묻는 질문에 답하기 어려웠다. 행동 이벤트를 시간순으로 나열하는 초기 구현도 DB 설명과 실제 재생 장면이 다른 경우가 있었다. 특히 여러 장면을 이어 붙인 영상에서는 긴 청크 하나에 행동 하나가 기록되어, 올바른 시간순 나열만으로는 믿을 만한 답변이 되지 않았다. 나는 질문 분기, 시퀀스 검색, 근거 구간 연결, 결과 화면과 원본 영상 검증을 담당했다.

### 접근과 구현

1. **질문 의도별 처리:** 전체 순서(FULL), 특정 장면의 앞·뒤(BEFORE/AFTER), 처음·마지막(FIRST/LAST)을 구분했다. 촬영 시각과 청크 정보를 바탕으로 이벤트를 정렬하고, 앞·뒤 질문에서는 기준 장면과 답변 장면을 함께 반환했다. 기준 행동이 모호하거나 영상에서 확인되지 않으면 임의의 후속 행동을 만들지 않도록 했다.
2. **근거 정합성 검증:** 기존 DB 이벤트 21건을 원본 MP4 두 편의 대표 장면과 대조했다. 일치 4건, 부분 일치 5건, 불일치 10건, 정지 프레임으로 판정 불가 2건이었다. 두 시연 영상에 한해 9건의 표현과 근거 시각을 수동 보정하고 나머지 12건을 시퀀스 답변에서 제외했다. 답변에는 제외 건수와 누락 가능성을 표시했다.
3. **검색·재생 연결:** 단계별 타임라인 카드에 대표 프레임과 청크 내 재생 구간을 연결해 사용자가 답변의 근거를 바로 확인할 수 있게 했다. 답변 텍스트도 결과 카드의 실제 장면 구간을 근거로 작성하도록 수정했다. 로컬 MP4 데모 서버를 마련해 검수된 결과를 재현했다.
4. **추출 단계 보완:** 새 이벤트는 시간 범위 안에 실제 추출 프레임이 없으면 저장하지 않고, 범위 가운데와 가장 가까운 프레임을 근거로 선택했다. 추출 프롬프트에는 종료 화면과 보이지 않는 소리·감정·의도 추정을 배제하는 지침을 추가했다.

### 확인된 결과와 한계

- 이벤트가 주어진 조건의 합성 시퀀스 질문 **43/43개**, 핵심 단위 테스트 **13/13개**가 통과했다. 이는 질문 해석과 정렬·선택 로직의 결과이며 영상 행동 인식 정확도가 아니다.
- 실제 DB를 이용한 두 시연 영상의 `/query` 응답에서 검수된 **3건과 6건**만 반환하고, 영상별 **6건씩** 제외했다. 이 결과는 수동 검수 데이터가 적용된 두 영상에 한정된다.
- 원본 대조를 통해 “문을 나간 다음 무엇을 했어?”처럼 질문이 전제하는 행동 자체가 확인되지 않을 때 답변을 보류하는 사례를 만들었다.
- 남은 문제는 긴 청크 안의 행동 경계 검출과 새 영상에서의 자동 검증이다. 이번 작업을 전체 서비스의 정확도 향상률이나 자동 추출 성능으로 표현하지 않는다.

### 포트폴리오 한 줄 성과

> 행동 순서·앞뒤·처음/마지막 질문을 처리하는 시퀀스 검색을 구현하고, 원본 영상 대조 후 불일치·판정 불가 근거 12건을 두 시연 영상의 답변에서 제외해 결과 카드와 실제 재생 장면을 연결했습니다.

## 자소서 문안

### 문제 해결 경험형

> 저는 기능이 정상 응답을 반환하는 것과 사용자가 그 답변을 믿을 수 있는 것은 다르다고 생각합니다. 반려동물 영상 검색 프로젝트에서 행동 순서 질문을 구현한 뒤, 저장된 이벤트 21건을 원본 영상과 대조했습니다. 시간순 정렬은 맞았지만 설명과 대표 장면이 불일치한 10건, 정지 프레임으로 판정할 수 없는 2건을 발견했습니다. 그래서 두 시연 영상의 검수 데이터를 별도로 만들고, 확인 가능한 9건만 표현과 재생 시각을 보정해 답변에 사용했습니다. 기준 행동이 보이지 않으면 다음 행동을 추측하지 않도록 질문 처리도 수정했습니다. 합성 시퀀스 질문 43개와 핵심 단위 테스트 13개를 통과했으며, 검증 범위가 두 영상에 한정된다는 사실도 답변에 표시했습니다. 이 경험을 통해 AI 기능은 생성된 문장뿐 아니라 사용자가 직접 확인할 수 있는 근거까지 함께 설계해야 한다는 기준을 갖게 됐습니다.

### 백엔드·AI 직무형

> 자연어 영상 검색 서비스에서 행동 순서 질문을 전체 순서, 앞뒤, 처음·마지막 유형으로 분리해 처리했습니다. 이벤트의 시각과 청크 정보를 기준으로 순서를 계산하고, 기준 장면이 모호하거나 확인되지 않으면 답변을 보류하도록 했습니다. 이후 원본 영상 두 편과 기존 이벤트 21건을 대조해 설명과 재생 장면의 불일치를 확인했습니다. 검수된 9건의 근거 시각과 표현을 보정하고 12건을 제외했으며, API 응답과 타임라인 카드에 같은 장면 구간을 연결했습니다. 합성 질문 43/43개와 핵심 단위 테스트 13/13개를 통과했습니다. 이 과정을 통해 검색 로직의 정답 여부와 입력 데이터의 신뢰도를 분리해 검증하는 방법을 배웠습니다.

### 협업·판단 경험형

> 팀 프로젝트에서 시퀀스 질문을 맡아 기능을 완성한 뒤, 발표용 결과를 원본 영상으로 다시 확인했습니다. 이벤트 21건 중 불일치 10건과 판정 불가 2건이 드러나자, 숫자를 좋게 보이게 하기보다 검수된 장면만 노출하기로 판단했습니다. 두 시연 영상에서는 9건을 보정해 사용하고 12건을 제외했으며, 제외 건수와 누락 가능성도 답변에 명시했습니다. 팀의 집계 질문 작업과는 역할을 구분해 진행하면서, 결과를 설명할 때도 시퀀스 로직 검증과 행동 추출 정확도를 혼동하지 않도록 정리했습니다. 제한을 드러내는 방식이 사용자에게 더 검증 가능한 결과를 준다는 것을 배웠습니다.

## 별도 확장 소재: Event Extraction 실험

이 부분은 **오프라인 실험** 경험으로만 사용한다. 개인 수행 범위를 확인한 뒤 지원서에 넣고, 서비스에 적용해 성능을 개선했다고 쓰지 않는다.

> 영상 행동 추출에서 놓치는 장면의 원인을 확인하기 위해 동일한 프레임과 영상 4개를 사용해 직접 추출, 관찰 후 추출, 후보 생성 후 검증 방식을 비교했습니다. 후보 생성 후 검증 방식은 근사 정답 13개 기준 느슨한 재현율이 5/13에서 11/13으로 높았지만, 엄격 정밀도는 5/8에서 7/35로 낮아졌습니다. 이어 검증 모델을 바꾼 오프라인 실험에서는 잘못된 후보 승인율을 19/20에서 2/20으로 낮추는 대신, 맞는 후보 승인도 16/17에서 7/17로 줄었습니다. 이 결과로 한 지표의 개선만 보고 모델을 교체하기보다, 오탐·누락·비용을 함께 검토해야 한다는 판단 기준을 세웠습니다.

실험은 각 방식 1회, 소수 영상에 한정된다. 정답 판정에는 프레임을 본 모델의 판단이 포함되어 있고 사람 다수 검수 정답이 아니다. Jev 비교의 승인율은 **Jev 이미지 판단과 사전 키워드 규칙의 결합 결과**다.

## 지원서에 옮길 때 확인할 것

- 시퀀스 검색·UI·추출 보완은 Git 커밋으로 본인 기여가 확인된다. 집계 질문의 상태 전환 및 횟수 계산은 팀원 담당이므로 본인 단독 구현으로 쓰지 않는다.
- **43/43**은 합성 시퀀스 검색 검증, **21건**은 기존 이벤트와 대표 장면의 수동 대조, **9건/12건**은 두 시연 영상에 적용한 검수 결과로 각각 구분한다.
- 검색 필터 재배치와 집계 부정 표현 처리 등 현재 작업 트리의 미커밋 변경은 완료 성과로 넣지 않았다.
- 회사·직무·문항 글자 수가 정해지면 위 문안에서 관련 사례 하나만 선택하고, 요구 역량에 맞춰 도입과 마무리를 조정한다.
