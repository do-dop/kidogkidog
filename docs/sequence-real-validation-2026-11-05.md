## 근거 장면 열기 확인

- `funny_moments`의 이벤트 41·60·62가 가리키는 프레임 키는 각각 GCS 녹화 청크 하나에 연결됐다. GCS에는 이 영상의 청크 9개가 존재한다.
- 마지막 이벤트 62의 청크를 실제 `/media/s3` 라우터로 `Range: bytes=0-1023` 요청하니 HTTP **206**, `video/mp4`, 1,024바이트를 반환했다.
- 문제 이벤트 60·62의 프레임 키를 같은 미디어 라우터로 요청하니 각각 HTTP **200**, `image/jpeg`를 반환했다.
- React 검색 화면에서 `강아지가 어떤 순서로 행동했어?`를 제출하자 답변과 관련 장면 3개가 표시됐다. 처음에는 API의 `object_labels` 배열을 문자열로만 처리해 화면이 실패했으나, 배열과 문자열 모두 처리하도록 수정했다.
- 첫 번째 장면 카드는 `_000.mp4`를, 두 번째는 `_001.mp4`를, 세 번째는 `_002.mp4`를 열었다. 세 번째 장면을 누른 뒤 브라우저의 실제 `<video>`에서 `readyState=3`, `paused=false`, `currentTime` 0.25초→1.02초 진행과 1920×1080 프레임을 확인했다. [재생 화면](sequence-ui-playback-2026-11-05.png)에 허스키가 테이블 앞에 있는 영상 프레임이 보인다. 0초 시작 장면도 메타데이터 로드 후 재생하도록 수정했다.
- 따라서 **검색 결과를 누르면 해당 녹화 청크가 플레이어에 열리고 재생되는 것**은 확인했다. 다만 답변 설명과 화면의 행동 일치 여부는 별개이며, 위 두 오탐 사례가 남아 있다. 검색 답변의 이벤트 시각 `16:17:59`와 카드·재생 청크 시각 `16:17:02`처럼 시각 표기도 서로 달라 정리가 필요하다.

## 결론과 우선 수정점

1. **시간 정렬과 빈 날짜 처리: 확인됨.** 두 실제 DB 영상에서 청크 간 시간순 반환과 빈 결과 처리가 동작했다.
2. **행동 설명·추출 정확도: 미통과.** 종료 화면 오탐과 근거 장면 불일치가 있다. 짧은 행동 구간 추출, 장면 전환/종료 화면 제외, 설명과 근거 프레임의 일치 검사가 우선이다.
3. **전체 흐름 표시: 미통과.** `funny_moments2`는 12개 중 10개만 API에서 반환한다. 현재 검색 화면은 `top_k=3`으로 요청하므로 더 많이 잘린다. 전체 타임라인을 보여주려면 표시 한도와 페이지 처리 정책을 정해야 한다.
4. **SmartHome-Bench 영상 정확도: 아직 미검증.** 이번 실제 DB 검증은 로컬에 원본이 있는 두 영상으로 했다. SmartHome-Bench 후보는 현재 원본 URL과 잠정 수기 관찰만 있다.
