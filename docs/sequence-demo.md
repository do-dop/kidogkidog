# 시퀀스 질문 데모와 평가

## 현재 동작

- 예시 질문: `오늘 강아지가 어떤 순서로 행동했어?`, `행동 흐름을 보여줘`, `수영장 장면 다음에는 뭐가 나와?`
- `behavior_events`를 시간순으로 조회한다. 청크 안의 초 단위 `timestamp`만 비교하지 않고, 프레임 키의 촬영 시작 시각과 청크 번호를 합쳐 순서를 정한다.
- 화면에는 시간순 설명과 각 이벤트의 근거 장면을 함께 보여준다.
- 답변의 `기록된 행동 이벤트`는 실제 모든 행동을 뜻하지 않는다. 영상 분석에서 추출·저장된 구간만 포함한다.

### 지금 처리하는 시퀀스 질문

| 유형 | 예시 | 동작 |
|---|---|---|
| 전체 순서 | `행동을 시간순으로 알려줘` | 확인된 장면을 시간순으로 표시 |
| 첫·마지막 | `처음에는 뭐 했어?`, `마지막에는 뭐 했어?` | 확인된 첫·마지막 장면 하나를 표시 |
| 특정 장면 다음 | `수영장 장면 다음에는 뭐가 나와?` | 기준 장면을 찾고 다음으로 확인된 장면 하나를 표시 |
| 특정 장면 이전 | `문 아래로 몸을 내밀기 전에는 뭐가 나와?` | 기준 장면 직전으로 확인된 장면 하나를 표시 |

앞·뒤 질문은 영상을 선택해야 한다. 기준 장면이 여러 개로 모호하거나 해당 행동이 확인되지 않으면 임의로 다음 행동을 만들지 않는다. 두 검수 영상은 여러 동물을 이어 붙인 모음집이라, `다음 장면`은 **영상 속 시간 순서**이며 같은 동물의 연속 행동을 뜻하지 않는다. `문을 나간 다음 뭐했어?`의 경우 문으로 몸을 내민 장면은 보이지만 완전히 나간 행동은 검증되지 않았다고 답한다.

실제 `funny_moments` DB를 사용한 API 확인: `수영장 장면 다음에는 뭐가 나와?` → 문 아래 출입구로 몸을 내민 장면(ID 59)을 반환한다. `문을 나간 다음 뭐했어?` → 완전히 나간 행동이 검증되지 않았다고 답하며 근거 카드는 반환하지 않는다. `문 아래로 몸을 내민 다음 뭐했어?` → 그 뒤 검증된 장면이 없다고 답한다.

## SmartHome-Bench 활용

원본: https://huggingface.co/datasets/violetcliff/SmartHome-Bench

직접 확인한 영상과 시연 질문은 [SmartHome-Bench 시퀀스 영상 검토](smarthome-bench-sequence-screening.md)에 정리했다. 우선 시연할 반려동물 사례는 `0009`, `0019`, `0041`, `0065`다. 표의 초 단위 구간은 아직 잠정치이므로 최종 정확도 점수에 사용하지 않는다.

이 데이터셋은 스마트홈 영상 1,203개 중 공개 영상 1,023개의 URL과 영어 영상 설명·이상 여부 주석을 제공한다. 허깅페이스 저장소에 영상 파일이 직접 들어 있지 않다. 공식 주석에는 행동별 시작·종료 시각이 없으므로 시퀀스 질문의 정답 구간은 별도 표기해야 한다. 데이터셋 페이지의 라이선스는 CC BY-NC-ND 4.0이며, 원본 YouTube 영상은 개별 제공자의 이용 조건도 확인한다.

평가 절차:

1. `Video_Annotation.csv`에서 `Pet Monitoring` 5~10개를 고르고, `Video_url.csv`의 공개 링크가 재생되는지 확인한다.
2. 각 영상의 뚜렷한 행동 2~4개를 직접 보며 시작·종료 초와 행동 문장을 적는다. 영상 설명만 보고 시각을 추정하지 않는다.
3. 같은 영상을 서비스에 넣고 시퀀스 질문을 실행한다.
4. 출력 순서가 정답과 같은지, 각 결과를 클릭했을 때 해당 장면이 재생되는지 확인한다.
5. 실패를 `이벤트 누락`, `행동 설명 오류`, `순서 오류`, `재생 구간 오류`로 나눠 기록한다.

정답 기록 형식:

| video_id | 순서 | 시작초 | 종료초 | 관찰한 행동 | 근거 메모 |
|---|---:|---:|---:|---|---|
| sample | 1 | 0 | 5 | 예: 고양이가 들어옴 | 직접 영상 확인 후 기입 |

## 노트북 현장 시연 체크

실행형 검증 노트북: [sequence-question-results.ipynb](../notebooks/sequence-question-results.ipynb). 앞부분은 DB 없이 가상 이벤트로 바로 실행할 수 있고, 마지막 API 셀은 실제 분석이 끝난 영상 ID를 입력한 뒤 실행한다.

기존 DB 영상과 로컬 원본을 대조한 첫 실제 검증 결과: [sequence-real-validation-2026-11-05.md](sequence-real-validation-2026-11-05.md). 시간 정렬은 동작했지만 종료 화면 오탐과 근거 불일치를 확인했다.

### 실제 영상 테스트 순서

1. 로컬 Jupyter 또는 VS Code에서 노트북의 앞부분을 실행해 `바닥 → 소파 → 내려옴 → 재등장`과 빈 날짜 응답을 확인한다. 이는 DB 없이 실행된다.
2. 서비스에 넣을 수 있는 **로컬 영상 파일**을 준비한다. SmartHome-Bench의 공개 페이지에는 URL만 있으므로, 그 링크가 곧바로 처리 가능한 로컬 파일은 아니다. 파일명을 `smartbench_0065.mp4`처럼 지정하면 시뮬레이터의 `video_id`가 `smartbench_0065`가 된다.
3. `readme.md`의 로컬 실행 순서에 따라 Chroma 터널, RabbitMQ, API, worker를 실행한다. `.env`의 GCS·MySQL 연결 및 업로드 권한이 실제로 동작해야 한다.
4. 영상 파일 하나만 `python -m dotenv -f .env run -- python -m simulator.edge_simulator data/videos/smartbench_0065.mp4 --server-url http://localhost:8000 --interval 5`로 처리한다. 업로드 응답은 **작업 접수**만 의미하므로 worker 로그와 DB 이벤트 생성까지 확인한다.
5. 노트북의 `video_id`와 필요하면 `recording_date`를 설정해 마지막 API 셀을 실행한다. 답변의 `query_type=sequence`, 행동 순서, `source_event_id`·재생 시점, 원본 영상의 행동을 비교한다. 다른 영상도 같은 절차로 반복한다.

검색 화면에서는 현재 `top_k=3`으로 요청한다. 네 행동을 보는 `0065` 전체 검증에는 노트북/API의 `top_k=10`을 사용한다. API 응답이 맞아도 화면에서 네 번째 항목이나 클릭 재생이 빠지면 화면 테스트는 실패로 기록한다.

1. **노트북과 충전기 지참.** 인터넷, 백엔드, 프론트엔드, DB·Chroma 연결 상태를 미리 확인한다.
2. 분석이 끝난 같은 영상에서 시퀀스 질문을 실행한다.
3. 첫째·둘째 결과를 눌러 답변 순서와 실제 영상 시점이 일치하는지 보여준다.
4. 이벤트가 없는 날짜를 선택해 근거가 없을 때 임의의 순서를 만들지 않는 것도 보여준다.
5. 집계형(`몇 번`)은 [aggregate-question-results.ipynb](../notebooks/aggregate-question-results.ipynb)의 영상·날짜와 같은 조건으로 비교한다. 집계형은 행동 구간(episode) 수를 세며, 구간 내부의 반복 횟수는 세지 않는다.

## 질문 라우팅

`run_rag_query`는 질문을 이 순서로 가른다.

1. 집계형(`몇 번`, `횟수` 등): `aggregate_query`가 처리한다. 시퀀스 판정보다 먼저 검사한다.
2. 추천 질문에서 넘어온 `source_event_id`: 해당 이벤트 구간 안에서만 근거를 찾는다.
3. 시퀀스형(`순서`, `흐름`, `타임라인`, `다음`, `이전` 등): `sequence_query`가 전체 순서 또는 기준 장면의 앞·뒤를 돌려준다.
4. 그 외: CLIP 검색과 행동 이벤트 기반 RAG 답변.

`question_router`의 `SEQUENCE` 분류는 아직 shadow 모드 로그용이며, 시퀀스 경로 선택에는 `is_sequence_query` 키워드 판정만 쓴다. 기준 행동 하나의 앞·뒤 질문은 처리하지만 `A가 B보다 먼저였어?`처럼 두 행동의 순서를 비교하는 질문은 아직 별도 처리하지 않는다.

## 다음 품질 우선순위

1. 추출 단계는 청크당 최대 20개 행동 구간을 분석·저장하고 긴 행동 이벤트는 쪼개어 저장한다. 그래도 일부 구간이 빠질 수 있으므로 시퀀스 평가는 이 누락률을 먼저 측정한다.
2. `A가 B보다 먼저였어?`, `A와 B 사이에 뭐 했어?` 같은 두 행동 관계 질문은 행동명 두 개의 매칭과 관계 검증을 별도 구현해야 한다.
3. 날짜 필터는 프레임 키의 이름 규칙에 의존한다. 시퀀스·집계 경로 모두 같은 규칙을 쓰므로 녹화 절대 시각을 DB 컬럼으로 저장하면 더 안정적이다.
4. `sequence_query`와 `question_router`의 시퀀스 판정을 하나로 합치고, 합친 뒤의 오분류율을 shadow 로그로 측정한다.
