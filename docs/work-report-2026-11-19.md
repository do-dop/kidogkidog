# 작업 정리: 펫캠 파이프라인 효율·정확도 점검과 개선 (2026-11-19)

## 1. 한 줄 요약

장시간 펫캠 영상(30분 × 2)으로 파이프라인을 점검해 비효율과 오차 3가지를 찾아 고쳤고(PR #72, #76), 행동 이벤트 추출을 "프레임 6장 → gpt-4o-mini"에서 "영상 직접 → Gemini"로 바꿀 수 있는 선택 옵션을 구현했다(PR #78). 같은 클립 6개에서 엄격 재현율이 33%에서 81%로 올랐다. 실제 60초 청크에서의 지연·비용은 아직 재지 않았다.

## 2. 파이프라인 점검 (로컬, 외부 업로드 없음)

- 대상: YouTube 라이브에서 받은 저활동 영상 2개(고양이, 강아지), 각 30분. 실제 분할 → 모션 감지 → 프레임 추출 → YOLO → CLIP → 분리된 로컬 ChromaDB.
- 운영 DB·저장소에는 쓰지 않았다. 영상은 `.gitignore`(`*.mp4`)로 저장소에도 올라가지 않는다. 출처 약관상 재배포 허용 여부가 확인되지 않아 평가용으로만 썼다.

| 발견 | 수치 |
|---|---|
| 추출 프레임 | 2,206장 (고양이 1,401, 강아지 805) |
| "모션 없음 → 전체 샘플링" 경로가 만든 프레임 | 1,986장 (약 90%). 이 경로가 `IDLE_SAMPLE_INTERVAL_SECONDS` 설정을 읽지 않았다 |
| 처리 시간 | 모션 감지 영상당 약 25초, YOLO 141초, CLIP·저장 686초 → 비용은 후속 모델에 집중 |
| 청크 길이 | 60초로 요청했지만 실제 58.3~66.7초. `청크번호×60` 시각 계산이 최대 8.3초 어긋남 |
| 인덱싱 무결성 | 누락 0, 비정상 벡터 0, 메타데이터 불일치 0, 재삽입 시 개수 불변 |
| 재삽입 시 메타데이터 | 같은 프레임 ID를 다시 넣으면 예전 timestamp가 그대로 남음 |
| YOLO 오탐 | 고양이 영상의 회색 담요를 dog으로 인식(confidence 0.50~0.60). 134개 프레임에 저장됨 |
| 인접 프레임 유사도 | 같은 청크 안 인접 프레임 코사인 유사도 중앙값 0.9975 |

## 3. 개선 (PR #72, #76 — 병합 완료)

- **#72** 정지 청크도 idle 간격(기본 2초)을 따르게 했다. 60초 청크 기준 추출 프레임은 2,206장에서 1,880장(고양이 908, 강아지 972)으로 약 15% 줄었다. 점검 중 이 수정이 다른 변경과 겹쳐 빠진 것을 발견해 복구했다.
- **#72** 첫 청크가 68.36초로 길어지던 문제를 `-segment_time_delta 0.05`로 고쳤다. 수정 후 최대 오차 0.023초. 합성 영상에서는 재현되지 않고 실제 영상에서만 나타난 문제였다.
- **#72** 이미 색인된 프레임을 다시 넣으면 임베딩은 재계산하지 않고 메타데이터만 갱신한다.
- **#72** `YOLO_CLASS_CONFIDENCE="dog=0.6"`처럼 클래스별 임계값 옵션(기본 꺼짐). 샘플 영상 2개에서 오탐은 0.50~0.60이고 실제 강아지 중앙값은 약 0.7이라 0.6이면 오탐은 사라지지만 일부 실제 강아지도 빠진다. 더 확인한 뒤 켜야 한다.
- **#76** 코드 곳곳의 `60`을 `CHUNK_SECONDS`(기본 60, 환경변수) 한 곳으로 모았다. 동작은 그대로다.
- 이전 세션의 #66(검색 순위 영상 크기 보정)은 세트 A Hit@1 9/18→14/18, 처음 보는 질문 세트 B 4/16→9/16이었다.

## 4. 청크 길이 비교 (60초 vs 300초, 결론 보류)

같은 30분 영상 2개, 수정된 코드, 로컬.

| 영상 | 청크 | 청크 수 | 프레임 | 추출 시간 | 경계에 걸린 모션 구간 |
|---|---|---:|---:|---:|---:|
| 강아지 | 60초 | 30 | 972 | 73초 | 6 |
| 강아지 | 300초 | 6 | 1,080 | 123초 | 0 |
| 고양이 | 60초 | 30 | 908 | 57초 | 0 |
| 고양이 | 300초 | 6 | 941 | 78초 | 0 |

- 300초는 프레임이 4~11% 많고 추출이 38~68% 느리지만 청크 수가 5분의 1이고 경계에서 잘리는 모션 구간이 없다.
- 청크 수에서 오는 업로드·큐·DB 기록·worker 시작 비용, 실패 시 재처리량, 결과가 나오기까지의 대기는 재지 않았다. 이것이 길이를 정하는 핵심 근거라 결론은 스테이징 측정 뒤로 미뤘다.
- 60초는 짧은 클립을 이어 붙인 테스트 영상에 맞춘 값으로 보이며, 장시간 펫캠의 기본값으로 검증된 적이 없다.

## 5. YOLO 종 필터 효과

필터: 질문한 동물이 없고 반대 동물만 감지된 프레임을 검색 결과에서 제외.

- **로컬(영상 2개)**: 상위 10 정밀도 변화 없음. 필터가 정답 영상 프레임 49장을 잘못 제거(담요 오탐 등), 틀린 영상 프레임 28장을 제거. 영상이 개 전용·고양이 전용 둘뿐이라 필터가 할 일이 없는 환경이다.
- **스테이징(질문 38개, 5회 반복 측정)**: 필터 켬(현재) 1위 적중 20/38, 3위 안 23/38, MRR 0.557. 끔 18/38, 22/38, 0.518. 결과가 달라진 질문은 6개(도움 4, 해침 2).
- 따라서 필터는 유지한다. 차이가 2건이라 단정하기엔 약하다. 첫 비교에서 끈 쪽이 좋아 보인 것은 서버가 막 시작해 프레임 수 보정이 적용되지 않은 영향이어서 서버를 데운 뒤 다시 쟀다.
- 측정용으로 만든 트래픽 0%의 태그 리비전은 지우고 설정을 원래대로 복구했다.

## 6. 행동 이벤트 추출: 프레임 방식 vs 영상 직접 입력

**현재 흐름**: 프레임을 모션 구간별로 묶고(12초 초과 시 12초 창, 2초 겹침) 프레임 많은 묶음부터 청크당 최대 8개를 고른 뒤 묶음마다 6장만 `gpt-4o-mini`에 보낸다. 묶음의 첫·끝 프레임은 Gemini(장면 변화 비교)에 별도로 간다. 정지 구간의 보조 프레임도 묶음이 되어 VLM으로 간다. 6장·8개·12초 값의 근거를 기록한 문서나 측정은 없다.

**비교 설계**: 보지 않은 클립 6개(14~34초), 정답 27개(근사 경계), 방식당 2회. 클립마다 4개 실행을 섞어 A~D로 이름 붙이고 시각과 행동 문장만 보고 판정한 뒤 방식 매핑을 열었다.

| 방식 | 엄격 재현율 | 느슨 재현율 | 이벤트 수 | 엄격 정밀도 |
|---|---:|---:|---:|---:|
| 프레임 (현재) | 9.0/27 (33%) | 16.5/27 (61%) | 24.5 | 37% |
| 영상 직접 (Gemini) | 22.0/27 (81%) | 25.0/27 (93%) | 39.5 | 56% |

- 프레임 방식은 설명이 "반려동물이 ~함"으로 뭉뚱그려져 행동이 어긋나는 경우가 많았다. 영상 방식은 외형·개체 수·위치·방향을 함께 얻었다.
- 영상 방식도 "대상이 화면에 없는 구간"은 맞히지 못했고 오히려 행동을 적었다. 금지한 감정 표현("맛있게")과 추측이 일부 섞였고, 이벤트가 많아 한 행동을 쪼갠 경우가 있다.

**구현(PR #78, 병합 완료)**
- 환경변수 `BEHAVIOR_EVENT_SOURCE`: `frames`(기본, 동작 불변) / `video`(실패 시 프레임으로 대체) / `both`(프레임 결과만 DB 저장, 영상 결과는 파일로만 저장).
- 결과를 기존 이벤트 형태로 맞춰 저장·검색 코드는 그대로 쓴다. 영상이 12MB 이하면 직접 담고 크면 Files API로 올린 뒤 삭제한다.
- 단위 테스트 23개 추가, 전체 360개 통과. 실제 Gemini 호출로 두 경로를 각 1회 확인(18초, 35초).
- **PR #80(미병합)**: worker Ansible 설정에 변수와 섀도 결과 마운트를 추가. 기본값은 `frames`.

## 7. 한계와 미검증

- 판정자와 정답 작성자가 같은 한 명(Claude)이고 정답은 근사 경계, 사람 검수가 없다. 시각과 문장만 보여 줘도 문체(프레임은 "~함", 영상은 긴 문장)로 방식이 짐작되어 완전한 가림이 아니다.
- 비교 클립은 6개, 14~34초라 실제 60초 청크가 아니다. 프레임 방식 두 번의 실행이 거의 같아 독립 표본이 적다.
- 점검 영상은 저활동 영상 2개(하나는 3분할 합성(위 2칸 + 아래 1칸))이고 행동이 많은 영상에서의 idle 2초 효과, 짧은 행동 누락 여부는 직접 재지 못했다. 이전 측정(행동 영상 14개)에서 idle 6초만으로 정답 구간 적중이 81%에서 96%였고, 2초는 그보다 촘촘하지만 2초와 1초를 직접 비교하지는 않았다.
- 영상 직접 입력의 지연·비용·실패율은 재지 않았다. 이전 실험의 응답 시간은 재시도 대기가 섞여 신뢰할 수 없다.
- **개인정보·약관**: 영상 방식은 영상을 Google로 전송한다. 지금까지는 공개 데이터셋과 평가용 영상만 썼다. 실제 사용자 영상에는 동의와 약관 검토가 필요해서 기본값을 `frames`로 두었다.

## 7-2. 실제 60초 청크 측정 (로컬, 영상 방식만 유효)

스테이징 배포가 막혀 같은 호출을 로컬에서 60초 청크로 측정했다(`experiments/both-mode-local-2026-11-19/REPORT.md`). 영상 방식(Gemini) 호출 218건 모두 성공했고 지연 중앙값은 5~24초, p95는 14~38초였다. 다만 강아지 영상에서 한 번 1,193초가 걸렸고 원인은 모른다(호출 전체 시간 상한 필요). 같은 시기 프레임 방식 쪽은 OpenAI 크레딧 소진(429)으로 대체 이벤트만 나와 이 측정의 프레임 방식 수치는 무효다. 고양이 합성 화면을 3칸으로 나눠 돌리면 이벤트가 약 2.5배 나오지만, 같은 행동의 반복 분할과 환각 의심이 섞여 있어 정확도 개선으로 해석할 수 없다.

## 7-3. YOLO 담요 오탐 완화 (`pipeline/models/species_verifier.py`)

confidence 임계값만 올리면 오탐은 줄지만 실제 강아지도 같이 빠진다(dog 박스 193개 중 0.6 미만 37개, 19%). 그래서 **YOLO conf < 0.65인 dog 박스만** 크롭해 CLIP으로 "강아지처럼 보이는가"를 다시 보고, 강아지 확률이 0.7 미만이면 버린다. 확신이 높은 감지는 CLIP을 거치지 않으며, CLIP 확인이 실패하면 감지를 유지한다. 끄려면 `YOLO_VERIFY_DOG=0`, 값은 `YOLO_VERIFY_MAX_CONF`, `YOLO_VERIFY_MIN_DOG_PROB`로 바꾼다.

| 방식(로컬 영상 2개, 20초 간격 샘플) | 고양이 영상 오탐 제거 | 강아지 영상 정상 감지 손실 |
|---|---:|---:|
| conf ≥ 0.6만 | 30/45 | 37/193 |
| conf < 0.65 & CLIP < 0.7 (채택) | 34/45 | 16/193 |
| 실제 `detect_objects` 프레임 단위 전/후 | dog 라벨 39 → 4 프레임(90프레임 중) | 87 → 85 프레임(90프레임 중) |

한계: 임계값을 측정에 쓴 같은 영상으로 골랐고, "실제 강아지"는 사람이 확인한 정답이 아니라 강아지 영상의 YOLO 감지를 그대로 쓴 것이다. 영상 2개·샘플 간격 20초라 서로 비슷한 프레임이 많다. 스테이징 영상으로 다시 확인해야 한다. CLIP 호출은 저신뢰 dog 박스에서만 생긴다.
