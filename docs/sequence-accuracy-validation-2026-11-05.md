## 발표용 실행 자료

[`notebooks/sequence-question-results.ipynb`](../notebooks/sequence-question-results.ipynb)는 질문 분류·정렬·근거 연결을 실행해 보여주는 노트북이다. 앞부분은 **가상 이벤트 스모크 테스트**이며, 실제 분석 정확도를 측정한 결과가 아니다. 실제 정확도는 아래 원본 영상 대조표를 사용한다.

## 범위와 판정법

- DB에 이미 저장된 `funny_moments` 9건, `funny_moments2` 12건을 읽기 전용으로 조회했다. 원본은 로컬 MP4 두 개(각 496초·650초)이다.
- 각 이벤트의 `source_frames`가 가리키는 대표 시점의 원본 프레임을 확인했다. 원본 영상에서 약 10초마다 프레임을 추가 추출하여 청크 전체의 장면 구성도 점검했다. [21건 대표 프레임 모음](sequence-accuracy-contact-sheet-2026-11-05.png).
- **일치**: 대표 프레임에서 핵심 행동이 보임. **부분**: 일부 맥락은 맞지만 핵심 행동·의도는 확인되지 않음. **불일치**: 설명이 대표 장면과 어긋남. **판정 보류**: 소리·움직임 등 정지 프레임만으로 핵심 주장을 검증할 수 없음.
- 이 수치는 **반환된 이벤트 설명과 근거 시점의 정합률**이다. 전체 영상의 모든 실제 행동을 라벨링하지 않았으므로 행동 검출 재현율이나 모델 전체 정확도는 아니다. 한 명의 평가자가 육안 판정했으며 청각 주장은 별도 검증하지 않았다.

## 시퀀스 기능 자체

- 두 영상의 21건은 코드의 기록 시각 기준으로 시간순 반환되었다. 두 번째 영상의 마지막 청크에 있는 이벤트 74(602초)와 73(604.5초)도 순서가 맞다.
- 하지만 **이벤트 21건 중 19건의 저장 구간은 30초 이상**이다. 여러 짧은 장면을 이어 붙인 영상에 청크당 대체로 하나의 이벤트만 저장되어, 출력 순서는 영상 청크 순서에 가깝다. 한 장면 안에서 ‘A 다음 B’를 묻는 질문의 정확도를 입증하지 못한다.
- API `top_k` 상한은 10이고 현재 화면 기본 요청은 3이다. 12건인 영상 2의 전체 시퀀스는 기본 화면에서 3건, API 최대 요청에서도 10건만 보인다.
- 답변의 시각은 `source_frames` 파일명에 기록된 청크 시작 시각에 이벤트의 상대 시간을 더한 값이다. 화면이 여는 원본 청크의 재생 시각과 사용자가 보는 ‘영상 전체 n초’는 다른 기준이므로, 발표 시에는 영상 전체 기준 초와 청크 내 재생 초를 함께 명시해야 한다.

## 다음 수정 우선순위

1. 원본 영상을 **장면 전환 기준으로 분할**하고 한 행동에 맞는 짧은 시작·종료 시각을 저장한다. 모음집 전체 1분 청크를 하나의 행동으로 요약하지 않는다.
2. 설명을 생성할 때 대표 구간 영상과 다시 대조해, 보이지 않는 물체·행동·의도·감정은 답변에서 제외한다. 종료 카드 등 비행동 화면을 필터링한다.
3. 시퀀스 답변에는 검증된 행동만 사용하고, 전체 순서에 필요한 이벤트는 페이지 또는 타임라인으로 모두 보여준다. 현재 3건 제한은 ‘처음 3건’임을 분명하게 표기한다.
4. 추후 SmartHome-Bench로 확장할 때는 **그 데이터셋 원본 영상에서 별도 정답 구간을 라벨링**해 행동 검출 정밀도·재현율과 순서 질의 정확도를 구분해 평가한다. 이번 21건 수치를 그 데이터셋 성능으로 일반화하지 않는다.
