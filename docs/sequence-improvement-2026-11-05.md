# 시퀀스 검색 개선 — 2026-11-05

## 이전 검색 흐름

1. 질문에 `순서`, `시간순`, `다음에` 등이 포함되면 시퀀스 경로로 분기한다.
2. 해당 영상의 `behavior_events`를 DB에서 읽어 `source_frames` 파일명과 이벤트 시작 시각으로 정렬한다.
3. 저장된 `summary`를 그대로 답변에 나열하고, 각 이벤트의 **첫 번째** 근거 프레임 주위 0~7초 등을 재생 카드로 돌려준다.

이 흐름은 정렬과 재생 연결은 동작하지만 저장된 설명의 정확도를 확인하지 않았다. 두 오래된 시연 영상에서는 약 1분짜리 모음집 청크가 행동 하나로 저장되어, 사료 먹기 설명에 수영장 장면을 연결하는 식의 불일치가 생겼다.

## 이번 변경

- [원본 대조 판정표](sequence-accuracy-validation-2026-11-05.md)에서 확인한 두 영상에만 수기 검수 데이터를 적용한다. 승인된 9개 이벤트는 원본에서 보이는 내용으로 설명을 고치고 검수한 2초 프레임을 재생 근거로 고정했다. 불일치 10개와 소리 때문에 판정 보류한 2개는 시퀀스 답변에서 제외한다.
- API 응답에 `excluded_event_count`를 추가하고, 답변에 제외 건수와 **전체 영상의 모든 행동을 뜻하지 않는다**는 한계를 표시한다. DB의 원본 이벤트는 바꾸지 않았다.
- 새 분석에서는 이벤트 시간 안에 실제 추출 프레임이 없으면 저장하지 않고, 시간 범위 가운데에 가장 가까운 프레임 하나를 근거로 남긴다. VLM 프롬프트에는 종료 카드 제외와 보이지 않는 소리·감정·의도 추정 금지를 추가했다.

|---|---:|---:|---:|---|
| `funny_moments` | 9 | 3 | 6 | HTTP 200, ID 41·44·59, 근거 모두 청크 내 2초 |
| `funny_moments2` | 12 | 6 | 6 | HTTP 200, ID 65·66·67·68·70·74, 근거 모두 청크 내 2초 |

검색 경로 단위 테스트 9개와 이벤트 시간 창 테스트 4개가 통과했다. 실제 `/query` 라우터도 두 영상 모두 `TestClient`에서 HTTP 200과 위 승인 목록을 반환했다.

## 해석과 남은 일

**검색에 표시되는 설명과 대표 장면의 일치성을 높이기 위한 보수적 수정**이다. 21개 중 9개만 보여주므로 재현율은 낮다. 수기 검수는 이 두 영상에만 적용되며, 새 영상의 의미 정확도는 아직 측정하지 않았다. 새 이벤트의 시간·근거 선택과 프롬프트는 개선했지만 실제 재처리 후 원본 대조 평가가 필요하다. 일반 서비스에서는 수기 검수 JSON을 관리자 검수 상태나 자동 영상 재검증 단계로 바꾸고, 장면 전환에 맞춘 더 짧은 구간 추출을 적용해야 한다.

## 앞·뒤 질문 추가

`수영장 장면 다음에는 뭐가 나와?`, `문 아래로 몸을 내밀기 전에는 뭐가 나와?`, `처음에는 뭐가 나와?`, `마지막에는 뭐가 나와?`를 시퀀스 경로에서 처리한다. 기준 장면을 하나로 찾은 뒤 다음/이전의 **검증된 장면 한 개**만 반환한다. 기준이 모호하거나 질문이 주장한 행동이 확인되지 않으면 임의의 다음 행동을 만들지 않는다. 실제 `문을 나간 다음 뭐했어?`에는 완전한 외출이 검증되지 않았다고 답한다. 여러 동물의 모음집이므로 다음 *장면*과 같은 동물의 다음 *행동*은 구분한다.
